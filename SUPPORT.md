# Support

Thanks for using 3ngram. Here is the fastest way to get the help you need.

## Where to go

| You want to… | Go to |
|---|---|
| Ask a question, get setup help, or discuss an idea | [GitHub Discussions](https://github.com/B3dmar/3ngram/discussions) |
| Report a reproducible bug | [Open a bug issue](https://github.com/B3dmar/3ngram/issues/new?template=bug.yml) |
| Request a feature | [Open a feature issue](https://github.com/B3dmar/3ngram/issues/new?template=feature.yml) |
| Report a security vulnerability | [Private security advisory](https://github.com/B3dmar/3ngram/security/advisories/new) — see [`SECURITY.md`](SECURITY.md) |
| Self-host 3ngram | [`docs/self-host.mdx`](docs/self-host.mdx) |

## Issues vs. Discussions

**Issues are reserved for actionable, reproducible bugs and concrete feature
requests** so the backlog stays a true work queue. Questions, "how do I…",
configuration help, and open-ended ideas belong in **GitHub Discussions**.
Question-style issues may be converted to a Discussion.

Before opening anything, please search existing issues and discussions — your
question may already be answered.

## What to include

When you do open a bug issue, the template asks for the essentials: what you
expected, what happened, the version/commit, and minimal reproduction steps. The
more precise the repro, the faster it can be fixed.

## Maintenance and response times

3ngram is maintained by a single person on a best-effort basis (see
[`MAINTAINERS.md`](MAINTAINERS.md)). There is no commercial support tier and no
SLA. Well-scoped, reproducible reports get attention soonest.
